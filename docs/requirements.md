# 모바일 웹 커뮤니티 서비스 요구사항 정의서

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.0 |
| 작성일 | 2026-11-22 |
| 대상 플랫폼 | 모바일 웹 (반응형, 최소 360px ~ 최대 480px 기준 레이아웃) |
| 기술 스택 | Next.js (App Router), Supabase (Auth / Database / Storage), Tailwind CSS, Vercel |

---

## 0. 개요

### 0.1 서비스 목적
사용자가 짧은 글을 작성하고, 다른 사용자의 글에 댓글과 좋아요로 소통하는 모바일 중심의 커뮤니티 서비스.

### 0.2 하단 탭 구성

| 탭 | 경로 | 설명 |
| --- | --- | --- |
| 홈 | `/` | 전체 게시글 피드 |
| 내정보 | `/me` | 내 프로필 및 내가 쓴 글 |
| 설정 | `/settings` | 프로필 수정 진입, 로그아웃 등 |

### 0.3 사용자 구분

| 구분 | 설명 |
| --- | --- |
| 비회원 | 로그인하지 않은 사용자. 피드·글 상세·다른 유저 프로필 **열람만** 가능 |
| 회원 | 로그인한 사용자. 글 작성, 댓글, 좋아요, 프로필 수정 가능 |

> 비회원 열람 허용 여부는 정책에 따라 변경 가능하며, 본 문서는 "열람 허용 / 작성은 로그인 필요"를 기본값으로 한다.

## 2. 기능 상세 요구사항

### 2.1 인증

#### F-01 회원가입
- **입력 항목**
  | 항목 | 필수 | 검증 규칙 |
  | --- | --- | --- |
  | 이메일 | O | 이메일 형식, 중복 불가 |
  | 비밀번호 | O | 8자 이상, 영문+숫자 포함 |
  | 비밀번호 확인 | O | 비밀번호와 일치 |
  | 닉네임 | O | 2~12자, 한글/영문/숫자/밑줄(_), 중복 불가 |
- **처리**
  - Supabase Auth `signUp`으로 계정 생성.
  - 가입 성공 시 `profiles` 테이블에 행 생성(DB 트리거 또는 서버 액션). 프로필 이미지는 기본 이미지.
  - 이메일 인증 사용 여부는 Supabase 설정에 따름 (MVP: 이메일 인증 OFF 권장, 가입 즉시 로그인).
- **예외/메시지**
  - 이메일 중복: "이미 가입된 이메일입니다."
  - 닉네임 중복: "이미 사용 중인 닉네임입니다."
  - 검증 실패 시 해당 입력 필드 하단에 에러 메시지 표시.
- **완료 후**: 홈(피드)으로 이동.

#### F-02 로그인
- **입력**: 이메일, 비밀번호.
- **처리**: Supabase Auth `signInWithPassword`. 세션은 `@supabase/ssr` 기반 쿠키로 관리하여 서버 컴포넌트에서도 인증 상태 확인.
- **예외**: 인증 실패 시 "이메일 또는 비밀번호가 올바르지 않습니다." (어느 항목이 틀렸는지 구분하지 않음)
- **완료 후**: 로그인 전 접근하려던 페이지(`redirect` 쿼리) 또는 홈으로 이동.
- 로그인 화면에서 회원가입 화면으로 이동 링크 제공.

#### F-03 로그아웃
- 위치: 설정 탭.
- 확인 다이얼로그("로그아웃 하시겠습니까?") 후 `signOut` 실행.
- 완료 후 홈으로 이동, 비회원 상태로 전환.

### 2.2 게시글

#### F-04 글 작성
- **진입**: 홈 화면 우측 하단 플로팅 버튼(+) → `/posts/new`.
- **입력**
  | 항목 | 필수 | 규칙 |
  | --- | --- | --- |
  | 제목 | O | 1~50자 |
  | 본문 | O | 1~2,000자, 줄바꿈 유지 |
  | 이미지 | X | 1장, jpg/png/webp, 5MB 이하 (Supabase Storage `post-images` 버킷) |
- **처리**
  - 등록 버튼은 필수값이 채워졌을 때만 활성화.
  - 등록 중 버튼 비활성화 및 로딩 표시(중복 제출 방지).
  - 성공 시 작성한 글의 상세 화면으로 이동.
- **예외**: 작성 중 뒤로가기 시 "작성 중인 내용이 사라집니다" 확인.

#### F-05 글 목록(피드)
- **표시 항목(카드)**: 작성자 프로필 이미지·닉네임, 작성 시간(상대시간: "3분 전"), 제목, 본문 미리보기(최대 3줄), 이미지 썸네일(있을 경우), 좋아요 수, 댓글 수.
- **정렬**: 최신순(`created_at desc`).
- **페이징**: 무한 스크롤, 1회 20개 로드 (커서 기반 권장).
- **상호작용**
  - 카드 탭 → 글 상세.
  - 작성자 영역 탭 → 해당 유저 프로필.
- **빈 상태**: "아직 게시글이 없어요. 첫 글을 작성해보세요!"
- **새로고침**: 상단 당겨서 새로고침(pull-to-refresh) 또는 홈 탭 재탭 시 최상단 이동 + 갱신.

#### F-06 글 상세
- **경로**: `/posts/[id]`
- **표시 항목**: 작성자 정보(이미지, 닉네임 → 프로필 링크), 작성 시간, 제목, 본문 전체, 이미지(원본 비율), 좋아요 버튼·수, 댓글 수, 댓글 목록, 댓글 입력창(하단 고정).
- 작성자 본인일 경우 우측 상단 더보기(⋯) 메뉴에 수정/삭제 노출.
- 존재하지 않거나 삭제된 글: "삭제되었거나 존재하지 않는 게시글입니다." 표시.

#### F-07 글 수정/삭제
- 수정: 작성 화면을 재사용(`/posts/[id]/edit`), 기존 값 채움. 수정 시 `updated_at` 갱신, 상세에 "(수정됨)" 표시.
- 삭제: 확인 다이얼로그 후 삭제. 연관 댓글·좋아요는 함께 삭제(CASCADE). 삭제 후 홈으로 이동.
- 권한: 작성자 본인만 가능 (RLS로 서버 측에서도 강제).

### 2.3 댓글

#### F-08 댓글 작성
- 글 상세 하단 고정 입력창. 1~500자.
- 비회원이 입력창 탭 시 로그인 유도.
- 등록 후 입력창 초기화, 목록 최하단에 즉시 반영, 댓글 수 증가.

#### F-09 댓글 목록
- 표시 항목: 작성자 이미지·닉네임(→ 프로필 링크), 내용, 작성 시간.
- 정렬: 오래된 순(`created_at asc`).
- 대댓글은 MVP 범위 제외.

#### F-10 댓글 삭제
- 본인 댓글에만 삭제 버튼 노출. 확인 후 삭제, 댓글 수 감소.

### 2.4 좋아요

#### F-11 좋아요 / 취소
- 하트 아이콘 토글. 좋아요 상태면 채워진 하트(강조색), 아니면 빈 하트.
- 사용자당 게시글 1회만 가능 (`(post_id, user_id)` 유니크).
- 낙관적 업데이트(Optimistic UI): 탭 즉시 UI 반영, 실패 시 원복 및 토스트 "잠시 후 다시 시도해주세요".
- 비회원이 탭 시 로그인 유도.
- 피드 카드와 글 상세 모두에서 좋아요 수 표시 (토글은 상세에서 필수, 피드에서는 권장).

### 2.5 프로필

#### F-12 내 프로필 보기 (내정보 탭)
- **경로**: `/me` (비회원 접근 시 로그인 화면으로 이동)
- **표시 항목**: 프로필 이미지(원형), 닉네임, 작성 글 수, 받은 좋아요 수(선택), "프로필 수정" 버튼, 내가 쓴 글 목록(피드 카드와 동일 형식, 최신순, 무한 스크롤).
- 빈 상태: "아직 작성한 글이 없어요."

#### F-13 프로필 수정
- **경로**: `/me/edit` (내정보 탭 버튼 또는 설정 탭에서 진입)
- **수정 항목**
  - 프로필 이미지: 앨범에서 선택, jpg/png/webp, 2MB 이하, 업로드 전 미리보기. Supabase Storage `avatars` 버킷, 경로 `{user_id}/...`. "기본 이미지로 변경" 옵션 제공.
  - 닉네임: 회원가입과 동일한 검증 규칙 및 중복 확인.
- 저장 성공 시 토스트 "프로필이 수정되었어요" 후 내정보로 이동. 변경 사항은 기존 글·댓글의 작성자 표시에도 반영(작성자 정보는 `profiles` 조인으로 조회).

#### F-14 다른 유저 프로필 보기
- **경로**: `/users/[id]`
- **진입**: 피드 카드, 글 상세, 댓글의 작성자 영역 탭.
- **표시 항목**: 프로필 이미지, 닉네임, 작성 글 수, 해당 유저가 쓴 글 목록.
- 본인 ID로 접근 시 `/me`로 리다이렉트.
- 존재하지 않는 유저: "존재하지 않는 사용자입니다."

### 2.6 공통

#### F-15 하단 탭 내비게이션
- 화면 하단 고정, 3개 탭(홈/내정보/설정), 아이콘 + 라벨, 현재 탭 강조.
- iOS 안전영역(`env(safe-area-inset-bottom)`) 대응.
- 글 작성, 글 상세, 프로필 수정, 로그인/회원가입 화면에서는 하단 탭 숨김(상단 뒤로가기 헤더 사용).

#### F-16 접근 제어
- 로그인 필요 경로(`/posts/new`, `/posts/[id]/edit`, `/me`, `/me/edit`) 접근 시 Next.js middleware에서 `/login?redirect=원래경로`로 이동.
- 로그인 상태에서 `/login`, `/signup` 접근 시 홈으로 이동.
- 모든 쓰기 권한은 Supabase RLS로 DB 레벨에서 강제.

### 2.7 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 반응형 | 모바일 우선. 데스크톱에서는 최대 너비 480px 중앙 정렬 |
| 성능 | 피드 첫 화면 LCP 2.5초 이내 목표, 이미지는 `next/image`로 최적화 |
| 보안 | 모든 테이블 RLS 활성화, Supabase service role 키는 클라이언트 노출 금지, 사용자 입력은 텍스트로만 렌더링(XSS 방지) |
| 피드백 | 로딩 시 스켈레톤 UI, 성공/실패 시 토스트 메시지 |
| 접근성 | 터치 영역 최소 44×44px, 아이콘 버튼에 `aria-label` 제공 |
| 배포 | Vercel 배포, 환경변수(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`)는 Vercel 프로젝트 설정으로 관리 |

### 2.8 MVP 범위 제외 항목

## 3. 사용자 흐름

### 3.1 최초 진입 및 회원가입
```
앱 진입 → 홈(피드) 열람 (비회원)
   └─ 글쓰기 / 좋아요 / 댓글 / 내정보 탭 시도
         └─ 로그인 화면 → [회원가입] 링크
               └─ 회원가입 입력 → 검증 통과 → 가입 완료
                     └─ 자동 로그인 → 원래 하려던 화면(또는 홈)으로 이동
```

### 3.2 로그인
```
로그인 화면 → 이메일/비밀번호 입력 → [로그인]
   ├─ 성공 → redirect 경로 또는 홈
   └─ 실패 → 에러 메시지 표시 후 재입력
```

### 3.3 글 작성
```
홈 → [+] 플로팅 버튼 → 글 작성 화면
   → 제목/본문 입력 (+ 이미지 선택) → [등록]
   → 작성한 글 상세 화면 → 뒤로가기 시 홈 피드 최상단에 새 글 노출
```

### 3.4 글 열람 · 댓글 · 좋아요
```
홈 피드 → 게시글 카드 탭 → 글 상세
   ├─ [하트] 탭 → 좋아요 토글 (수 즉시 반영)
   ├─ 댓글 입력 → [등록] → 댓글 목록에 추가
   └─ 작성자 닉네임 탭 → 다른 유저 프로필
```

### 3.5 내 프로필 확인 및 수정
```
하단 [내정보] 탭 → 내 프로필 (이미지, 닉네임, 내가 쓴 글)
   ├─ 내가 쓴 글 탭 → 글 상세 (수정/삭제 가능)
   └─ [프로필 수정] → 이미지/닉네임 변경 → [저장] → 내정보로 복귀
```

### 3.6 다른 유저 프로필 보기
```
피드 카드 / 글 상세 / 댓글의 작성자 영역 탭
   → 유저 프로필 (이미지, 닉네임, 작성 글 목록)
   → 글 탭 → 글 상세
```

### 3.7 로그아웃

## 5. 데이터 개요

### 5.1 ERD (개념)
```
auth.users (Supabase 관리)
    │ 1:1
profiles ─────1:N───── posts ─────1:N───── comments
    │                    │                     │
    │                    └──1:N── likes ──N:1──┤ (profiles)
    └──────────────────1:N─────────────────────┘
```

### 5.2 테이블 정의

#### profiles — 사용자 프로필
| 컬럼 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| id | uuid | PK, FK → auth.users.id (ON DELETE CASCADE) | 사용자 ID |
| nickname | text | NOT NULL, UNIQUE, 2~12자 | 닉네임 |
| avatar_url | text | NULL 허용 | 프로필 이미지 URL (NULL이면 기본 이미지) |
| created_at | timestamptz | DEFAULT now() | 가입일 |
| updated_at | timestamptz | DEFAULT now() | 수정일 |

#### posts — 게시글
| 컬럼 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| id | bigint (identity) | PK | 게시글 ID |
| author_id | uuid | FK → profiles.id (ON DELETE CASCADE), NOT NULL | 작성자 |
| title | text | NOT NULL, 1~50자 | 제목 |
| content | text | NOT NULL, 1~2000자 | 본문 |
| image_url | text | NULL 허용 | 첨부 이미지 URL |
| like_count | int | DEFAULT 0 | 좋아요 수 (트리거로 갱신, 비정규화) |
| comment_count | int | DEFAULT 0 | 댓글 수 (트리거로 갱신, 비정규화) |
| created_at | timestamptz | DEFAULT now() | 작성일 |
| updated_at | timestamptz | DEFAULT now() | 수정일 |

- 인덱스: `(created_at desc)`, `(author_id, created_at desc)`

#### comments — 댓글
| 컬럼 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| id | bigint (identity) | PK | 댓글 ID |
| post_id | bigint | FK → posts.id (ON DELETE CASCADE), NOT NULL | 게시글 |
| author_id | uuid | FK → profiles.id (ON DELETE CASCADE), NOT NULL | 작성자 |
| content | text | NOT NULL, 1~500자 | 내용 |
| created_at | timestamptz | DEFAULT now() | 작성일 |

- 인덱스: `(post_id, created_at)`

#### likes — 좋아요
| 컬럼 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| post_id | bigint | FK → posts.id (ON DELETE CASCADE) | 게시글 |
| user_id | uuid | FK → profiles.id (ON DELETE CASCADE) | 좋아요한 사용자 |
| created_at | timestamptz | DEFAULT now() | 좋아요 일시 |

- PK: `(post_id, user_id)` — 중복 좋아요 방지

### 5.3 Storage 버킷
| 버킷 | 공개 여부 | 경로 규칙 | 용도 |
| --- | --- | --- | --- |
| avatars | public read | `{user_id}/{timestamp}.{ext}` | 프로필 이미지 |
| post-images | public read | `{user_id}/{timestamp}.{ext}` | 게시글 이미지 |

- 업로드/삭제는 경로의 첫 폴더가 본인 `user_id`인 경우에만 허용.

### 5.4 RLS 정책 요약
| 테이블 | SELECT | INSERT | UPDATE | DELETE |
| --- | --- | --- | --- | --- |
| profiles | 전체 | 본인(`id = auth.uid()`) | 본인 | - |
| posts | 전체 | 로그인 사용자(`author_id = auth.uid()`) | 작성자 | 작성자 |
| comments | 전체 | 로그인 사용자(`author_id = auth.uid()`) | - | 작성자 |
| likes | 전체 | 본인(`user_id = auth.uid()`) | - | 본인 |

### 5.5 트리거 / 함수
- `handle_new_user`: `auth.users` INSERT 시 `profiles` 행 생성 (가입 시 메타데이터의 nickname 사용).
- `update_like_count`: `likes` INSERT/DELETE 시 `posts.like_count` 증감.
- `update_comment_count`: `comments` INSERT/DELETE 시 `posts.comment_count` 증감.
- `set_updated_at`: `profiles`, `posts` UPDATE 시 `updated_at` 갱신.
